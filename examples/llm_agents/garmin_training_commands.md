# Garmin Training Commands For LLM Agents

Use these commands to create Garmin cycling training workouts from reviewed
RideFaster intent.

Safety defaults:

- Dry-run is the default for Garmin write operations.
- Use `--apply` only after reviewing the printed payload.
- Keep Garmin tokens outside the repository.
- Do not delete or unschedule workouts from an agent flow.
- Start with the harmless `RF Test Easy 10m` workout before real training.

## Build The Test Workout

```powershell
poetry run garmin-rf build-test-workout
```

Write the payload to an ignored local file:

```powershell
poetry run garmin-rf build-test-workout --output derived/ridefaster/rf_test_easy_10m.json
```

## Dry-Run A Garmin Upload And Schedule

```powershell
poetry run garmin-rf push-workout --date 2026-06-18 --dry-run
```

This prints the exact Garmin actions and workout JSON without logging in or
writing to Garmin.

## Apply A Reviewed Test Workout

```powershell
poetry run garmin-rf push-workout --date 2026-06-18 --apply
```

When applied, the command:

1. Logs in using the external Garmin token store.
2. Uploads the workout template to Garmin.
3. Schedules it on the selected date.
4. Records local sync state in `derived/ridefaster/workout_sync_state.json`.

## Push An Agent-Generated Workout JSON File

```powershell
poetry run garmin-rf push-workout --date 2026-06-18 --workout-json derived/ridefaster/rf_easy_10m.json --dry-run
poetry run garmin-rf push-workout --date 2026-06-18 --workout-json derived/ridefaster/rf_easy_10m.json --apply
```

## Inspect Existing Garmin State

```powershell
poetry run garmin-rf list-workouts --limit 25
poetry run garmin-rf list-scheduled --month 2026-06
```

These are read-only commands, but they still require valid Garmin tokens.

## Current Boundary

This command set intentionally avoids free-form weekly-plan parsing, workout
deletion, unscheduling, and unvalidated power targets. Add those only after the
basic upload, schedule, Garmin Connect calendar, and device sync path is proven.
